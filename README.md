# Сойдется?

**Считай, сравнивай, решай**

Демонстрационный образовательный тренажер для продавцов маркетплейсов: разработка интерактивной методики обучения обоснованию экономических решений в условиях неопределенности.

Проект подготовлен для стипендиального конкурса «Система» (номинация «Технологии электронной коммерции», тема «Развитие продавцов на маркетплейсе»). Это независимый конкурсный прототип, не официальный продукт Ozon. Интеграция и внедрение не согласованы.

## Версия 1.5

Пять отдельных экранов с навигацией и сохранением текущего задания при переходе между разделами. В версии 1.2 переработаны формулировки всех 11 заданий, добавлен раскрываемый учебный пример расчета (только в обучающем блоке), условия представлены в таблице «Без акции / В акции», упрощены заголовки, уточнены инструкции и обратная связь. Расчетное ядро, набор сценариев и правила начисления баллов сохранены. Обращение к пользователю на Вы. В версии 1.3 добавлены интерактивный сценарий на главной с общей расчетной моделью, наглядное разделение этапов обучения, визуальная обратная связь без раскрытия правильных ответов в контрольном блоке, разбор собственных ответов и сравнение положительных и отрицательных значений дохода на общей шкале.

В версии 1.4 уточнены границы оценивания и интерпретация порога, добавлены ближайшие аналоги и критический научный источник. Расчетный алгоритм и число заданий были сохранены. В версии 1.5 добавлены два учебных сценария, образующие полную матрицу 2 × 2 обоснованности вывода и исхода. Контрольный вопрос также изменен: правильный ответ теперь требует оценки конкретного вывода. Всего 9 + 4 задания, контроль по-прежнему максимум 6 баллов. Открытый учебный контроль не является исследовательским измерением.

## Что работает

- Интерактивный пример на главной: изменение числа продаж, маржинального дохода и достижения цели.
- Девять обучающих задач с объяснениями: экономический, информационный и результативный контрасты.
- Четыре контрольных задания без промежуточных подсказок (максимум 6 баллов за отдельные ответы).
- Калькулятор маржинального дохода и необходимого объема продаж с учетом дополнительных расходов, диапазона спроса и запаса товара.
- Описание методики, источники, ограничения и предполагаемая процедура проверки эффективности.

Все параметры условны. Тренажер не прогнозирует спрос, не выдает индивидуальных финансовых рекомендаций и не является психодиагностическим инструментом. Образовательная эффективность не установлена.

## Запуск и публикация

Откройте `index.html` в браузере с включенным JavaScript. Весь сайт, включая стили, логику и изображение фирменного знака, находится в одном файле; отдельный сервер, API, ключи и установка зависимостей для работы сайта не нужны.

Для GitHub Pages:

1. Создайте репозиторий `soydetsya` (или другое доступное имя). На GitHub Free для такого способа публикации нужен публичный репозиторий. Перед публикацией проверьте условия конкурса и отсутствие нежелательных для раскрытия данных.
2. Загрузите распакованные файлы из комплекта в корень репозитория (не ZIP и не папку-контейнер). `index.html` должен находиться на верхнем уровне.
3. В настройках репозитория откройте **Settings → Pages → Build and deployment**. Выберите **Deploy from a branch**, ветку **main**, папку **/ (root)**, нажмите **Save**. Если ветка называется иначе, выберите фактическую ветку.
4. После успешного развертывания откройте адрес, указанный в Pages, через **Visit site**. Пример адреса: `https://USERNAME.github.io/soydetsya/`. Это пример, не действующая ссылка.
5. Проверьте сайт в приватном окне браузера, пройдите задания, измените значения калькулятора. Для демонстрации используйте адрес Pages, а не ссылку на исходный HTML в репозитории.

Документация: [настройка Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site), [загрузка файлов](https://docs.github.com/en/repositories/working-with-files/managing-files/adding-a-file-to-a-repository).

## Технические проверки

Для пользователя тренажера установка программ не нужна. При желании разработчик может запустить `node test-core.cjs` (Node.js). Для браузерных тестов нужны Python и Playwright с установленным Chromium: `python -m pip install playwright`, `python -m playwright install chromium`, затем `python test-browser.py`. При наличии системного Chromium используется он; переменная `CHROMIUM_PATH` позволяет указать свой путь. По умолчанию тестируется точное содержимое `index.html`. При `TEST_HTTP=1` скрипт использует локальный HTTP-сервер (этот режим в среде подготовки был заблокирован административной политикой).

## Фирменный стиль

Использован утвержденный фирменный знак из визуальной концепции «Сойдется?», выделенный из растрового брендборда. Цвета: кобальтовый `#002EA8`, синий `#0A66FF`, голубой `#66C2FF`, серебристый `#D3DAE8`, фон `#F7F9FF`. Основной текст – темно-синий `#10275D`. Для автономной работы использован системный гротеск без внешних файлов шрифтов. Декоративные дуги и градиенты реализованы средствами CSS. Знак – растровая адаптация, не окончательный векторный оригинал.

## Использование искусственного интеллекта

Программный код, тестовые сценарии и исходная визуальная концепция подготовлены с помощью генеративного ИИ (ChatGPT). ИИ также использовался при аналитической и методической проработке проекта. Сам тренажер не использует нейросеть: вычисления и проверка закрытых ответов выполняются детерминированными правилами. Технические тесты не заменяют экспертной предметной проверки или исследования на пользователях. Участнику необходимо самостоятельно проверить содержание, зафиксировать собственный вклад и соблюдать требования организаторов к индивидуальному авторству и раскрытию использования ИИ.
